# Deploying to PythonAnywhere — hmmanya.pythonanywhere.com

Written for the account **`hmmanya`**, so every path and URL below can be copied
as-is. No virtualenv: dependencies install into your account with `pip --user`.

Work through it in order. Steps 1–7 get the site running; steps 8–10 add email,
Google Calendar and live chat.

> **Use `https://` everywhere.** Your site answers on both, but this app builds
> its own links as `https://` — PythonAnywhere terminates TLS at its proxy and
> forwards plain HTTP internally, so Django would otherwise generate `http://`
> URLs that Google rejects. Register `https://hmmanya.pythonanywhere.com` with
> Google and put `https://` in `.env`, even though `http://` also loads the site.

---

## 1. Get the code onto the server

*Consoles* tab → **Bash**:

```bash
cd ~
git clone <your-repo-url> hair-saloon
cd hair-saloon
```

Now find where `manage.py` actually is — this decides several paths later:

```bash
ls ~/hair-saloon/manage.py
```

If that errors, your repository keeps the project in a subfolder:

```bash
ls ~/hair-saloon/hair-saloon/manage.py
```

Whichever works is your **project folder**. This guide writes it as
`/home/hmmanya/hair-saloon`; if the nested path is the real one, use
`/home/hmmanya/hair-saloon/hair-saloon` everywhere instead. Run every command
below from that folder.

## 2. Install the dependencies

```bash
pip3.11 install --user -r requirements.txt
```

Three things to get right:

- **`--user` is required.** PythonAnywhere's system Python is read-only, so a
  plain `pip install` fails. `--user` installs into
  `~/.local/lib/python3.11/site-packages`, which is already on the path.
- **Use the versioned command** (`pip3.11`, not `pip`) and pick the *same*
  version on the Web tab in step 6. Installing with `pip3.11` and serving with
  Python 3.10 gives `ModuleNotFoundError: No module named 'django'` on a site
  that works perfectly in the console.
- **PythonAnywhere preinstalls its own Django**, usually older. Your `--user`
  install takes precedence, which is fine. Check with
  `python3.11 -m django --version`.

Everything below uses `python3.11` explicitly for the same reason.

## 3. Generate your DJANGO_SECRET_KEY

### What it is

One long random string Django uses to sign and encrypt things. In *this* project
it protects four of them:

| It secures | What breaks if it changes |
| --- | --- |
| Login sessions | Everyone is logged out |
| Accept / decline links in booking emails | Links already sent stop working |
| Customer cancellation links | Same |
| **Stored Google tokens and the OAuth client secret** | The Google connection dies — reconnect on `/manage/google/` |

That last row is the important one: the encryption key is *derived from*
`SECRET_KEY`. Set it once and leave it alone.

### Generate one

In a Bash console, from your project folder:

```bash
python3.11 -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

That prints a 50-character key from Django's own generator — the method to
prefer, because it produces exactly what Django expects:

```
8k2!m@3xq#7vz$0nb^wj5t(re9)yl4gp1c&hd6fs+u_a2imo0
```

Two alternatives if you prefer:

```bash
# Python standard library
python3.11 -c "import secrets; print(secrets.token_urlsafe(64))"

# OpenSSL
openssl rand -base64 64 | tr -d '\n'; echo
```

> Keys generated by `django-admin startproject` carry a `django-insecure-`
> prefix. `get_random_secret_key()` does not add one. Either is fine — what
> matters is that the value is random and secret.

### Rules

- **Copy it straight into `.env` (step 4). Do not commit it**, do not paste it
  into a chat or an issue, and do not put it in the WSGI file. `.gitignore`
  already excludes `.env`.
- **Never keep** the development default `dev-only-insecure-key-change-me`.
- If the key contains a `#`, wrap the value in quotes in `.env` — otherwise
  everything after the `#` is read as a comment:
  `DJANGO_SECRET_KEY="ab#cd..."`.
- If it ever leaks, generate a new one, reload, and reconnect Google.

## 4. Create your .env

```bash
cd ~/hair-saloon
cp .env.example .env
nano .env
```

Here is the whole file for this account — paste it, then replace the first line
with the key you just generated:

```ini
DJANGO_SECRET_KEY=paste-your-generated-key-here
DJANGO_DEBUG=False
DJANGO_ALLOWED_HOSTS=hmmanya.pythonanywhere.com
DJANGO_CSRF_TRUSTED_ORIGINS=https://hmmanya.pythonanywhere.com
SITE_BASE_URL=https://hmmanya.pythonanywhere.com
DJANGO_TIME_ZONE=Europe/Berlin
DECISION_LINK_MAX_AGE_DAYS=30
```

Save with `Ctrl+O`, `Enter`, exit with `Ctrl+X`.

What each line does:

- **`DJANGO_DEBUG=False`** — required in production. With it on, Django shows a
  full traceback, including settings, to anyone who triggers an error.
- **`DJANGO_ALLOWED_HOSTS`** — hostname only: no `https://`, no trailing slash.
  Getting this wrong is the most common cause of a 500 right after deploying.
- **`DJANGO_CSRF_TRUSTED_ORIGINS`** — this one *does* need `https://`. Without
  it the booking form and every admin POST fail CSRF validation.
- **`SITE_BASE_URL`** — what accept / decline links in emails point at. Wrong or
  missing, and those emails carry `http://127.0.0.1:8000/...` links that do
  nothing for the recipient.
- **`DJANGO_TIME_ZONE`** — change if you are not on Central European time; it
  governs how opening hours are interpreted.

Confirm it loaded:

```bash
python3.11 -c "from hairsaloon import settings; print(settings.DEBUG, settings.ALLOWED_HOSTS, settings.SITE_BASE_URL)"
```

Expect `False ['hmmanya.pythonanywhere.com'] https://hmmanya.pythonanywhere.com`.

## 5. Database and first data

```bash
python3.11 manage.py migrate
python3.11 manage.py init_salon --name "Your Salon" --timezone Europe/Berlin
python3.11 manage.py createsuperuser
python3.11 manage.py collectstatic --noinput
```

`init_salon` creates the settings row and a default Mon–Sat opening week (add
`--demo` for example services). `createsuperuser` is the login for `/admin/`,
`/manage/` and `/manage/google/` — choose a real password; that account can read
every customer's details.

SQLite is fine for one salon. For MySQL: create the database on the *Databases*
tab, `pip3.11 install --user mysqlclient`, fill in the `DB_*` lines in `.env`,
and re-run `migrate`.

## 6. Create the web app and its WSGI file

### 6a. Create the web app

*Web* tab → **Add a new web app**:

1. Domain: `hmmanya.pythonanywhere.com` (accept it).
2. Framework: **Manual configuration** — *not* the "Django" option, which
   generates its own project and would fight this one.
3. Python version: **3.11** — the same version you used with `pip3.11`.

### 6b. Fill in the paths

Still on the *Web* tab, **Code** section:

| Field | Value |
| --- | --- |
| Source code | `/home/hmmanya/hair-saloon` |
| Working directory | `/home/hmmanya/hair-saloon` |
| Virtualenv | **leave completely empty** |

(Use the nested path from step 1 if that is where `manage.py` lives.)

An empty Virtualenv box is what makes the web app use the system Python plus
your `--user` packages. Filling it in with a path that does not exist stops the
app from starting.

### 6c. The WSGI file — the step that catches everyone

The **WSGI configuration file** link in the Code section points at:

```
/var/www/hmmanya_pythonanywhere_com_wsgi.py
```

That file lives *outside* your project. Editing `pythonanywhere_wsgi.py` in the
repo does nothing by itself — you have to copy its contents into this one.

Click the link, **delete everything already in it** (it ships with a Django
example that will conflict), and paste:

```python
import os
import sys

USERNAME = "hmmanya"
PROJECT_DIR = f"/home/{USERNAME}/hair-saloon"

# Fall back to the nested layout automatically if that is where manage.py lives.
if not os.path.exists(os.path.join(PROJECT_DIR, "manage.py")):
    nested = os.path.join(PROJECT_DIR, "hair-saloon")
    if os.path.exists(os.path.join(nested, "manage.py")):
        PROJECT_DIR = nested
    else:
        raise RuntimeError(
            f"manage.py not found in {PROJECT_DIR} or {nested}. "
            "Set PROJECT_DIR to the folder that contains manage.py."
        )

if PROJECT_DIR not in sys.path:
    sys.path.insert(0, PROJECT_DIR)

os.environ["DJANGO_SETTINGS_MODULE"] = "hairsaloon.settings"

from django.core.wsgi import get_wsgi_application  # noqa: E402

application = get_wsgi_application()
```

This is the same content as `pythonanywhere_wsgi.py` in the repo, and it works
with either folder layout. Save it.

Notes:

- **No secrets in here.** `settings.py` reads `.env` from the project folder.
- `application` must exist at module level — that name is what the server looks
  for.
- If you ever move the project, this is the file to update.

### 6d. Static files

Still on the *Web* tab, **Static files** section, add two mappings:

| URL | Directory |
| --- | --- |
| `/static/` | `/home/hmmanya/hair-saloon/staticfiles` |
| `/media/` | `/home/hmmanya/hair-saloon/media` |

`/static/` is belt and braces, since WhiteNoise also serves it. `/media/` is
what makes uploaded stylist photos appear and is **not** covered by WhiteNoise.

### 6e. HTTPS

In the **Security** section, switch **Force HTTPS** on.

## 8. Email

**Nothing to configure.** Booking emails are sent through the Gmail API of the
Google account you connect in step 9 — the same account used for the calendar.
No SMTP host, no App Password.

This also sidesteps the usual PythonAnywhere headache: free accounts cannot open
outbound SMTP connections, but the Gmail API is an ordinary HTTPS call to
`googleapis.com`, which has to work anyway or the calendar sync would fail too.
So **email works on the free plan**.

Set only this, for the display name on outgoing mail:

```ini
DEFAULT_FROM_EMAIL=Your Salon <ignored@example.com>
```

The address is always the connected Google account — Gmail rewrites it — so only
the name in front matters.

Until you connect an account, emails are printed to the server log rather than
sent (`EMAIL_FALLBACK_TO_CONSOLE`, on in development, off in production).

<details>
<summary>Using your own SMTP server instead</summary>

Set `EMAIL_HOST` and the app switches to SMTP entirely:

```ini
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_HOST_USER=yoursalon@gmail.com
EMAIL_HOST_PASSWORD=abcd efgh ijkl mnop
DEFAULT_FROM_EMAIL=Your Salon <yoursalon@gmail.com>
```

With Gmail over SMTP you need an
[App Password](https://myaccount.google.com/apppasswords); your normal password
will not work. On a free PythonAnywhere account this route silently sends
nothing, because outbound SMTP is blocked.
</details>

## 9. Google Calendar

The salon-facing walkthrough is **built into the app**. Log in and open

```
https://hmmanya.pythonanywhere.com/manage/google/
```

then expand *"Never done this before? Full step-by-step"*. It shows your exact
redirect URI with a Copy button. What follows is the same material for reference.

### 9a. Create the Google Cloud project

1. <https://console.cloud.google.com/> → sign in with the **salon's** Google
   account → project dropdown → **New project** → name it `Salon Booking`.
2. **APIs & Services → Library** → enable **Google Calendar API**, and also
   **Gmail API** if you want the salon's booking emails sent from this account
   (recommended — it removes the need for any SMTP password). No credit card is
   needed.

### 9b. Consent screen

**APIs & Services → OAuth consent screen**:

1. **External** → Create. (*Internal* only exists on Google Workspace accounts.)
2. App name (`Salon Booking`), user support email, developer contact email.
   Customers never see these.
3. Skip **Scopes** — the app requests what it needs at connect time.
4. **Test users → Add users**: add the salon's Google address and any other
   account whose calendars you will connect. **Do not skip this** — while the
   app is unpublished, Google refuses any account not on the list with
   `access_denied`.
5. Optionally press **Publish app**. Left in *Testing*, a connection expires
   after 7 days and you would reconnect weekly. Publishing stops that and, for
   the calendar access used here, takes effect immediately without a review.

### 9c. Create the OAuth client

**APIs & Services → Credentials → Create credentials → OAuth client ID**:

1. Application type: **Web application** — not Desktop; the website is what
   signs in.
2. Name: `Salon website`.
3. **Authorised redirect URIs → Add URI**, exactly:

   ```
   https://hmmanya.pythonanywhere.com/manage/google/callback/
   ```

   **`https://`, and keep the trailing slash.** Your site also answers on
   `http://`, but the app always sends `https://` to Google, so an `http://`
   entry here produces `redirect_uri_mismatch`. Leave *Authorised JavaScript
   origins* empty.
4. **Create**, then copy the **Client ID** and **Client secret**.

### 9d. Connect, then add calendars

1. Open `https://hmmanya.pythonanywhere.com/manage/google/`.
2. Paste the Client ID and Client Secret → **Save client**. The secret is stored
   encrypted.
3. **Connect a Google account** → sign in. Google warns the app is not verified,
   which is expected for your own project: **Advanced → Go to … (unsafe)** →
   **Allow**.
4. Section 3 now lists that account's calendars. For each one you want, type the
   name customers should see, set the address for accept / decline emails, and
   click **Add**. It appears on the homepage immediately.

For one calendar per stylist, create extra calendars inside the same Google
account (calendar.google.com → *Other calendars* → **+** → *Create new
calendar*), reload the setup page, and add them the same way — no reconnecting
and no sharing needed. The second guide on that page covers it in full.

Verify from a console at any time:

```bash
cd ~/hair-saloon && python3.11 manage.py check_google
```

## 10. Live chat (optional)

Off by default. Switch it on at
`https://hmmanya.pythonanywhere.com/chat/desk/`.

If you use it, schedule the transcript purge — transcripts are personal data and
nothing deletes them without this job. *Tasks* tab → daily:

```
cd ~/hair-saloon && python3.11 manage.py purge_old_chats
```

Free accounts get one daily task, which is exactly enough.

Chat polls over HTTP (no WebSockets on these plans), so an open chat window is
about one small request every 5 seconds. If your CPU allowance is tight, raise
**Chat settings → poll seconds**. By default chat follows your business hours and
closes itself when the salon does.

## Updating later

```bash
cd ~/hair-saloon
bash deploy.sh --pull
```

| Flag | Effect |
| --- | --- |
| `--pull` | `git pull` before deploying |
| `--test` | run the test suite before reloading |
| `--no-reload` | everything except touching the WSGI file |
| `--help` | print the usage block |

It installs dependencies, migrates, collects static files, runs Django's checks
and reloads the web app — warning about a missing `.env`, `DEBUG` left on, an
unset `SITE_BASE_URL`, or migrations that have drifted. It never runs plain
`makemigrations`, never touches `db.sqlite3` or `media/`, and never edits `.env`.

Pin the interpreter with `PYTHON=python3.11 bash deploy.sh` if auto-detection
picks the wrong one, or point it at the WSGI file with
`WSGI_FILE=/var/www/hmmanya_pythonanywhere_com_wsgi.py`.

By hand:

```bash
cd ~/hair-saloon
git pull
pip3.11 install --user -r requirements.txt
python3.11 manage.py migrate
python3.11 manage.py collectstatic --noinput
```

Then **Reload** on the Web tab.

## When something breaks

Always start with *Web → Error log*, newest lines at the bottom.

| Symptom | Cause |
| --- | --- |
| `DisallowedHost`, or a 500 right after deploying | `DJANGO_ALLOWED_HOSTS` must be `hmmanya.pythonanywhere.com` — hostname only, no scheme |
| `ModuleNotFoundError: No module named 'hairsaloon'` | `PROJECT_DIR` in the WSGI file is not the folder holding `manage.py` |
| `ModuleNotFoundError: No module named 'django'`, but the console works | Web tab Python version ≠ the `pip3.11` you installed with |
| `error: externally-managed-environment` from pip | You left out `--user` |
| CSRF error on the booking form | `DJANGO_CSRF_TRUSTED_ORIGINS` needs `https://hmmanya.pythonanywhere.com` |
| Site loads with no styling | Re-run `collectstatic`; check the `/static/` mapping |
| Stylist photos missing | The `/media/` static mapping is absent |
| Accept / decline links point at `127.0.0.1` | `SITE_BASE_URL` is wrong. Fix and reload; links already sent stay broken |
| `redirect_uri_mismatch` | The URI at Google is not exactly `https://hmmanya.pythonanywhere.com/manage/google/callback/` |
| `access_denied` on the consent screen | That address is not in **Test users**, or you pressed Cancel |
| "Google did not return a refresh token" | Remove the app at <https://myaccount.google.com/permissions>, then connect again |
| Google connection dies after editing `.env` | You changed `DJANGO_SECRET_KEY`; reconnect on `/manage/google/` |
| Everyone suddenly logged out | Same cause — `SECRET_KEY` changed |
| Google connection stops working after 7 days | The consent screen is still in *Testing*. **Publish app** |
| Bookings save but never reach Google | See *Google sync error* on the appointment in the admin, fix it, then **Re-sync** |
| No emails at all | Check `manage.py check_google` — the connection may lack the email grant; reconnect at `/manage/google/` |
| "This connection cannot send email yet" | Connected before email sending existed. Press **Reconnect** and approve the extra permission |
