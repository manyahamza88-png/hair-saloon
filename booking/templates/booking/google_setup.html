In the Google Cloud console: enable the Google Calendar API, then Create credentials → OAuth client ID → Web application.

Never done this before? Full step-by-step — about 10 minutes

You are creating a small "app" in Google's developer console that this website uses to talk to your calendar. It is free, and you only do it once. You need a Google account — ideally the salon's account, not a personal one.

1. Create a project

  1. Go to console.cloud.google.com and sign in with the salon's Google account.
  2. Accept the terms if you are asked. You do not need to enter a credit card — calendar access is free.
  3. Click the project dropdown in the blue bar at the top → New project.
  4. Name it something like Salon Booking and click Create.
  5. Wait a few seconds, then make sure that project is selected in the dropdown. Everything below must happen inside it.

2. Switch on the Calendar API

  1. Left menu → APIs & Services → Library.
  2. Search for Google Calendar API, open it, click Enable.
  3. Go back to the Library, search for Gmail API and enable that too.

The Gmail API lets the salon's booking emails be sent from this account, so there is no SMTP server or app password to set up — and it works on hosts that block outbound SMTP. The permission requested is gmail.send, which can only send mail; it cannot read the mailbox. Skip it if you would rather configure your own SMTP server.

3. Fill in the consent screen

This is the "… wants access to your Google Account" page you will see when connecting.

  1. APIs & Services → OAuth consent screen.
  2. Choose External and click Create. (Internal only exists on Google Workspace accounts; External is right for an ordinary Gmail account.)
  3. Fill in the required fields: an App name (customers never see it — "Salon Booking" is fine), a User support email, and a Developer contact email. Leave the rest empty.
  4. Save and continue through Scopes without adding anything — this app requests what it needs at connect time.
  5. On Test users, click Add users and enter every Google address whose calendars you will connect (usually just the salon's). This step matters: while the app is unpublished, Google refuses any account that is not on this list with access_denied.
  6. Save and continue to the summary.

Leaving the app in Testing is fine and needs no review from Google. The only catch is that a connection expires after 7 days, so you would reconnect here weekly. To stop that, press Publish app on this screen: for the calendar access used here, publishing takes effect immediately and does not require Google's verification review.

4. Create the OAuth client

  1. APIs & Services → Credentials → Create credentials → OAuth client ID.
  2. Application type: Web application. (Not "Desktop" — this website is the thing signing in.)
  3. Give it a name, e.g. Salon website.
  4. Under Authorised redirect URIs, click Add URI and paste exactly this:
    {{ callback_url }}
    Nothing else goes in that box. Do not add a redirect URI under "Authorised JavaScript origins" — it belongs in the redirect list.
  5. Click Create. Google shows your Client ID and Client secret.
  6. Copy both into the two fields below on this page and press Save client. You can always reopen the credential in the console to copy them again.

5. Connect, and you are done

Use Connect a Google account in step 2 below. Google will warn that the app is not verified — that is expected for your own app; choose Advanced → Go to … (unsafe) and continue. You are granting access to your own calendar, from your own project.

If something goes wrong

redirect_uri_mismatch The URI in the console is not character-for-character the one shown above. Watch for a missing trailing slash or http instead of https.
access_denied That Google address is not in Test users (step 3), or you clicked Cancel.
invalid_client Client ID or secret was mistyped. Re-copy both and save again.
"Google did not return a refresh token" This account already granted access. Remove the app at myaccount.google.com/permissions and connect again.
Calendar API not enabled Step 2 was skipped, or you did it in a different project than the one holding the credentials.
Add this exact Authorised redirect URI to that OAuth client:
{{ callback_url }}
It must match character for character, including https:// and the trailing slash.

Connect one account for the whole salon, or one per stylist — every calendar on the site is tied to the account it came from, so a stylist can link their own Google account and keep their own calendar on their own phone.

How to give each stylist their own calendar — and put it on the homepage

Two ways round this, and you can mix them.

A. One salon account, one calendar per stylist

Simplest to run: you hold the single Google login.

  1. Open calendar.google.com signed in as the connected salon account.
  2. Left sidebar → Other calendars → + → Create new calendar. Name it after the stylist and set the salon's time zone.
  3. Reload this page — the new calendar appears under that account below.
  4. Type the name customers should see, set the address for accept / decline emails (the stylist's own address works well), and press Add.
  5. Share it with the stylist in Google Calendar → that calendar's settings → Share with specific people, so it shows on their phone.

B. Each stylist connects their own Google account

Best when stylists already live in their own Google Calendar and you would rather not share logins.

  1. Sign in to this site as staff on the stylist's device (or have them sit with you).
  2. Press Connect another Google account below and sign in as them.
  3. Their account appears as its own block, listing their calendars.
  4. Add whichever calendar should take bookings, and name it for customers.

Each account is independent: disconnecting one leaves the others working. Bookings are written into whichever account owns that calendar, so a stylist only ever sees their own appointments.

Then, in the admin

  • Photo, description and accent colour for the homepage card;
  • opening hours for that calendar alone (leave empty to use the salon's);
  • that stylist's own time off, separate from salon-wide closures;
  • which services they offer, and the order their card appears in.

Good to know

  • Removing a calendar from the site never deletes anything in Google.
  • Appointments already in a calendar are respected straight away: the free/busy check hides time that is already taken.
  • A calendar the account can only read cannot be added — bookings have to be writable into it.
